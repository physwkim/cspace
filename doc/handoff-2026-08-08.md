## 3. cxx_min / cxx_max / cxx_clamp — 결정 완료, 통합은 merge 이후

C++ `std::min(a,b)`는 `b<a?b:a`, `std::max(a,b)`는 `a<b?b:a` — 비교가 거짓이면
둘 다 `a`를 돌려준다(NaN 포함). Rust `f64::min/max`는 non-NaN 피연산자를
돌려주고 `f64::clamp`는 NaN 경계에서 **panic**한다. 그래서 손으로 쓴 shim을
쓴다.

정본은 `crates/moveit-trajectory/src/numeric.rs`:
```rust
pub(crate) fn cxx_min(a: f64, b: f64) -> f64 { if b < a { b } else { a } }
pub(crate) fn cxx_max(a: f64, b: f64) -> f64 { if a < b { b } else { a } }
pub(crate) fn cxx_clamp(v: f64, lo: f64, hi: f64) -> f64 {
    if v < lo { lo } else if hi < v { hi } else { v }
}
```

현재 triage 브랜치 기준 `cxx_min` 3개 크레이트(trajectory, kinematics, scene),
`cxx_max` 2개, `cxx_clamp` 1개. **본문은 전부 byte-identical.**

**결정:** 지금은 크레이트별 복제를 유지한다. 공유 크레이트로 승격하는 것은
workspace member/Cargo.toml 변경이라 살아 있는 5개 브랜치와 충돌한다. 브랜치가
수렴한 뒤 **단일 커밋**으로 통합한다. 의존 그래프상 모든 소비자가 이미 의존하는
leaf는 `moveit-error`뿐이고(moveit-* 의존 0개, 19개 중 18개가 의존), 의미상
정직한 답은 새 `moveit-numeric` leaf다. `moveit-geometry`는 불가 —
moveit-trajectory가 의존하지 않는다.

5개 패널 전원에게 "정본을 그대로 복사할 것, 새 철자를 만들지 말 것, 단독으로
승격하지 말 것"을 이미 통지했다.

## 6. 확인된 사실 (재도출 금지)

- 상류 트리는 `/home/stevek/work/moveit2` — **`third_party/` 아래가 아니다.**
  `third_party/`에는 geometric_shapes, moveit_msgs, moveit_resources, octomap,
  orocos_kinematics_dynamics, srdfdom만 있다. worktree에서는 상대 경로로 보이지
  않으므로 **절대 경로**를 써야 한다.
- `f4d0d1db` 검증 통과 — `robot_state.hpp:169,263,361,456`이 전부
  `assert(robot_model_->getVariableCount() <= X.size());  // checked only in
  debug mode` 이고, `double*` primitive(`:253,:348,:445`)는
  `memcpy(..., getVariableCount() * sizeof(double))`로 정확히 variable_count만
  복사한다. 긴 슬라이스의 꼬리는 읽히지 않는다.
- IEEE 754: `0.0 * NaN = NaN`, `0.0 * inf = NaN`. 내적은 상대 벡터가 0인 축에서
  NaN을 **지우지 못한다**. (두 패널이 독립적으로 반대 주장을 문서에 썼고, 실측
  probe로 반박했다. 그 뒤 내가 내놓은 무한대 대체 근거도 같은 방식으로 틀렸다 —
  근거를 반박했다고 해서 대체 근거를 책상에서 지어낼 수 없다.)
- C++ `assert()`는 NDEBUG에서 사라지고 Rust `assert!`는 안 사라진다. 충실한
  이식은 `debug_assert!`. 단 `copy_from_slice`는 모든 프로파일에서 본질적으로
  panic하므로 "downgrade" 대상이 아니다.
- FCL octree dispatch: `OcTreeShapeIntersectRecurse`는 점유 leaf마다 literal
  `Box`-vs-shape `shapeIntersect` 호출로 분해한다
  (`octree_solver-inl.h:342-346,367-374,384`).

## 8. 절차 (반복 위반 지점)

- caucus 알림/라운드 파일/`last_note`/`state`는 **신뢰할 수 없다.** 가장 싼
  판별은 화제 기반이다 — "이게 내가 마지막으로 보낸 brief에 답하고 있나?"
  보조로 `read_panel` mode `screen`과 worktree의 `git status --porcelain`.
- 워커 보고는 양방향으로 검증한다. 상류 인용은 파일을 열어서 확인한다.
- 하나의 finding = 하나의 커밋. 묶지 않는다.
- 커밋 전 `cargo fmt --all` → 만진 크레이트마다
  `cargo clippy -p <crate> --all-targets -- -D warnings` →
  `cargo nextest run -p <crate>`. 게이트를 파이프에 물리면 실패가 숨는다.
- 압축(compaction)을 건넌 수치는 **트리를 잃는다.** 경로는 남고 "어느 브랜치에서
  쟀는지"가 사라진다. 다시 재기 전에는 인용하지 않는다.
